# Spec Delta

## Purpose

Управление записью аудио встречи из popup: старт и стоп одной сессии, накопление webm и отправка на локальный сервер после Стоп.

## ADDED Requirements

### Requirement: Start recording
Popup SHALL предоставлять действие «Старт». По нажатию расширение SHALL проверить доступность сервера (`GET {serverUrl}/health` с `ok: true`), зафиксировать `sessionId` и момент старта, начать захват аудио целевой вкладки (без видео) и писать поток через MediaRecorder в формате `audio/webm` (предпочтительно Opus). Пока идёт запись, «Старт» SHALL быть недоступен, «Стоп» — доступен.

#### Scenario: Успешный старт
- **WHEN** сервер доступен и пользователь нажимает «Старт»
- **THEN** UI показывает состояние записи, начинается захват аудио целевой вкладки

#### Scenario: Старт при недоступном сервере
- **WHEN** health не отвечает или `ok` не true
- **THEN** запись не начинается, пользователю показывается ошибка о недоступности сервера

#### Scenario: Отказ в захвате вкладки
- **WHEN** браузер отклоняет захват аудио вкладки
- **THEN** запись не считается активной, пользователю показывается явная ошибка

### Requirement: Stop recording and upload
Popup SHALL предоставлять действие «Стоп». По нажатию расширение SHALL остановить MediaRecorder, дождаться финального Blob, сформировать multipart `POST {serverUrl}/v1/jobs` с полями `audio`, `speakers` (файл jsonl; в этом milestone допускается пустой или минимальный), `meta` (JSON-строка минимум с `sessionId`, `startedAtIso`, `durationSec`, `pageUrl`). После ответа `202` UI SHALL показать `id` job и опрашивать `GET /v1/jobs/{id}` до терминального статуса.

#### Scenario: Успешный стоп и upload
- **WHEN** идёт запись и пользователь нажимает «Стоп», сервер принимает job
- **THEN** Blob отправлен, UI показывает job id и обновляет статус по polling

#### Scenario: Стоп без активной записи
- **WHEN** запись не идёт
- **THEN** «Стоп» недоступен или не выполняет upload

### Requirement: Single session
В любой момент SHALL существовать не более одной активной сессии записи в расширении.

#### Scenario: Повторный старт во время записи
- **WHEN** запись уже активна
- **THEN** повторный «Старт» не создаёт вторую сессию
