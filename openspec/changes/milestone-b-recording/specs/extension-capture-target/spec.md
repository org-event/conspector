# Spec Delta

## Purpose

Пользователь видит, какую страницу/вкладку расширение слушает при записи, и может сменить цель захвата до старта.

## ADDED Requirements

### Requirement: Show capture target
До и во время записи popup SHALL показывать идентификацию цели захвата: как минимум URL (или title + URL) вкладки, с которой будет / идёт запись.

#### Scenario: Отображение активной вкладки
- **WHEN** popup открыт и цель — активная вкладка окна
- **THEN** пользователь видит URL этой вкладки в UI

### Requirement: Change capture target before start
Пока запись не идёт, пользователь SHALL иметь возможность сменить цель: выбрать другую вкладку (через активацию вкладки и обновление popup) и/или задать сохраняемый URL-паттерн (`captureUrlPattern` в `chrome.storage`), ограничивающий, на каких страницах имеет смысл вести запись/инжект. Значение паттерна SHALL сохраняться между открытиями popup.

#### Scenario: Смена вкладки до старта
- **WHEN** пользователь переключает активную вкладку и снова открывает popup (или обновляет цель)
- **THEN** отображаемая цель соответствует новой активной вкладке

#### Scenario: Сохранение URL-паттерна
- **WHEN** пользователь задаёт URL-паттерн цели и закрывает popup
- **THEN** при следующем открытии паттерн восстановлен из storage

#### Scenario: Старт при несоответствии паттерну
- **WHEN** задан непустой `captureUrlPattern` и URL активной вкладки ему не соответствует
- **THEN** «Старт» блокируется или показывает предупреждение (реализация выбирает одно; поведение SHALL быть явным в UI)

### Requirement: Target locked during recording
После успешного Старт цель захвата SHALL быть зафиксирована на выбранной вкладке до Стоп; смена активной вкладки пользователем не должна молча перенаправить запись на другую вкладку.

#### Scenario: Переключение вкладки во время записи
- **WHEN** запись идёт и пользователь активирует другую вкладку
- **THEN** запись продолжает относиться к исходной целевой вкладке, UI по-прежнему показывает исходную цель
