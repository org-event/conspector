# Design

## Context

Greenfield: в репозитории только план `conspector.md`. Целевая машина — macOS, i7-9750H, 16 GB RAM; прототип, не продакшен. Ограничения плана: запись/ASR/резюме появятся в следующих milestone, в этом — только каркас и контракты.

## Goals / Non-Goals

**Goals:**
- Рабочий сервер: `GET /health`, `POST /v1/jobs` (сохранение файлов + stub → `done`), `GET /v1/jobs/{id}`.
- Рабочий popup: сохранение `serverUrl` + индикатор доступности сервера.
- Структура каталогов и контракты, позволяющие добавлять запись (B), ASR (C), спикеров (D), резюме (E) без рефакторинга.

**Non-Goals:**
- Реальная запись аудио, content script, ASR, Ollama, селекторы DOM — следующие milestone.
- Docker, продакшен-харднинг, параллельные jobs.

## Decisions

1. **Сборка расширения: Vite + TypeScript без @crxjs/vite-plugin.**
   Для popup-страницы и будущих entry-точек (background, content) достаточно мульти-entry сборки Vite: `popup.html` как HTML-вход, `background.ts`/`content/*.ts` как JS-входы, `manifest.json` копируется в `dist/` настройкой Vite. Альтернатива — @crxjs/vite-plugin: больше «магии» (инжект манифеста, HMR) и версионная хрупкость, а для прототипа без HMR это лишний риск. Статический манифест из плана §2.1 остаётся источником прав.

2. **Сервер: FastAPI + uvicorn, jobs в памяти + файлы на диске.**
   Состояние jobs — `dict` в памяти процесса (id → статус/результат), файлы — `server/data/jobs/{id}/`. Альтернатива — SQLite: избыточна для локального прототипа с одним пользователем; потеря jobs при рестарте сервера приемлема (см. Риски).

3. **Stub-пайплайн: asyncio-задача, сразу переводящая job в `done`.**
   `POST /v1/jobs` создаёт job со статусом `queued` (ответ `202`), затем фоновая задача мгновенно ставит `done` с плейсхолдер-результатом. Так цикл статусов (`queued → done`) уже реален, и в milestone C/E stub заменяется реальными стадиями без изменения контракта.

4. **Конфиг: pydantic-settings, env-переменные с дефолтами из плана §4.2** (`HOST=127.0.0.1`, `PORT=8765`, `ASR_MODEL=small`, `OLLAMA_MODEL=qwen2.5:7b-instruct-q4_K_M`, `DATA_DIR=./data` и др.). Полный набор параметров определяется сразу, хотя ASR-параметры понадобятся только в milestone C: `GET /health` уже отдаёт `asrModel`/`llm` из конфига.

5. **Хранилище настроек расширения: `chrome.storage.local`.**
   План допускает sync или local; local проще (не требует аккаунта Google) и достаточен для локального прототипа.

6. **CORS: `CORSMiddleware` с `allow_origins=["*"]`.**
   Popup живёт в origin `chrome-extension://<id>`; сервер слушает только `127.0.0.1`, поэтому широкий CORS в прототипе безопасен.

7. **ID job: `job_` + uuid4 (hex).** Формат зафиксирован контрактом (§3 плана).

## Risks / Trade-offs

- [Jobs теряются при рестарте сервера (in-memory)] → для прототипа приемлемо; расширение в milestone B увидит 404 и покажет ошибку — поведение явное.
- [Статический манифест без crxjs] → при добавлении entry-точек (background/content) нужно не забыть про entry в конфиге Vite; зафиксировано в задачах.
- [Limit загрузки (MAX_UPLOAD_MB) не применяется в v1] → FastAPI без явной проверки размера; на локальном сервере риск минимален, контроль добавим при необходимости.
- [Stub `done` может замаскировать проблемы upload] → в задачах milestone A предусмотрен ручной прогон `curl` с реальными файлами для проверки сохранения.
